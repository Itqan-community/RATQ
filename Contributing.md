# Contributing to RATQ

Thank you for your interest in contributing to RATQ (Roadmap and Technologies for Qur'an)! This
project is a living, community-maintained knowledge base, so most contributions are edits and
additions to Markdown content rather than code changes.

## Code of Conduct

This project adheres to a Code of Conduct that all contributors, maintainers, and community members
are expected to follow. Please read [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) before contributing or
participating in any project space.

## How to Contribute

1. **Fork** the repository and clone your fork locally.
2. Create a branch for your change:
   ```bash
   git checkout -b docs/short-description-of-change
   ```
3. Make your change. Common contributions include:
   - Adding or updating an entry in [Technologies](./content/technologies/Technologies.md)
   - Adding or updating an entry in [Available Apps](./docs/available-apps.md)
   - Improving the [Development Roadmap](./docs/development-guidelines.md)
   - Fixing broken links, typos, or outdated information
4. Commit your change with a clear, descriptive message (e.g.
   `docs: add entry for <tool name> to Technologies list`).
5. Push your branch and open a pull request against `main`.
6. In your PR description, briefly explain **what** changed and **why** — for example, why a
   resource belongs in the list, or what gap the change fills.

## Pull Request Review

- A maintainer will review your PR and may ask for changes or clarification.
- PRs are merged once they're accurate, on-topic, and consistent with the structure of the existing
  content.
- Please keep PRs focused — one topic or resource per PR is easier to review than a large batch of
  unrelated changes.

## Governance

RATQ is maintained under the [Itqan community](https://itqan.dev). This section makes the current,
informal maintenance model explicit.

### Decision-Making

- Day-to-day content decisions (adding/updating/removing entries, fixing errors) are made by
  reviewing and merging pull requests — no separate approval process is required beyond a
  maintainer's review.
- Larger or structural changes (e.g. reorganizing the roadmap, changing how technologies are
  categorized) should be proposed in an issue first so they can be discussed before a PR is opened.
- Disagreements are resolved through discussion on the relevant issue or PR. If consensus can't be
  reached, a project maintainer makes the final call.

### Maintainer Access

- Merge/write access to this repository is held by members of the
  [Itqan-community](https://github.com/Itqan-community) organization with maintainer permissions on
  this repo.
- The current list of people with write access can always be checked via the repository's
  **Settings → Collaborators and teams** (visible to those with admin access) or by seeing who
  reviews and merges PRs in the [commit history](https://github.com/Itqan-community/RATQ/commits/main/).
- To request maintainer/write access, open an issue describing your contribution history and intent,
  or reach out via [connect@itqan.dev](mailto:connect@itqan.dev).

If you're not sure whether a contribution fits, or need help getting started, open an issue or reach
